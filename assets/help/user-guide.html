MarineOps Help

All ledger data is stored locally. Select a record to see its available actions. Press F1 for contextual help. About is available beside the workspace tabs on Dashboard, Cargo and Personnel.

Quick start

  1. Open Fleet and choose Add vessel. The built-in shore location, initially xx port, is the same location formerly called On Shore. Set its shared name under Settings > Port name.
  2. Use Route actions > New voyage, add vessel visits and manually select Current stop.
  3. Choose Add cargo and enter Description, From and To. Physical ID and Comment are optional. Cargo can also be recorded without a voyage.

Cargo and status

Each physical cargo item has a stable Cargo ID. Transfers are separate legs with their own record numbers. Waiting means awaiting collection, On Board means collected by the transfer vessel, and Done means delivered. Pick up and Deliver record the confirmed location and completion date. A later transfer leg can be added after the previous delivery.

Current stop shows actions for the manually selected visit. Pick up and Deliver require confirmation of the actual location. Select a record and use Details for its transfer chain, location evidence and audit history. Edit fields changes editable details; the status dropdown records status changes in the audit history. Dates and status do not advance the current visit automatically.

Delete and restore

Delete removes an eligible completed record from normal views while preserving its history. Deleted records offers Restore. An On Board transfer cannot be voided until its physical state is resolved. A correction changes the recorded facts with an audit reason; it does not erase previous evidence. Invalid transitions and concurrent edits are rejected.

Fleet

Add or edit vessel names in Fleet. Inactive vessels remain in historical records. Deletion is blocked while active references require the vessel. Reusing a deleted vessel name does not replace its historical identity. Port name is managed in Settings, rather than as a second shore location.

Voyages and visits

Create a voyage and add visits from Fleet. Visits to the same vessel have distinct identities. Select a visit to make it Current; selecting Current again clears it. Drag visits to reorder, or use the visit menu to move or remove them. Current continues to refer to the same visit after reordering. A historical voyage is read-only; copy it to create a new working route.

Views, search and export

All transfers shows the ledger. Current stop shows relevant actions. On my vessel shows cargo that is On Board. Search includes Cargo ID, description, physical ID and comments. Status and vessel filters can be combined. Clear filters resets them. Summary counts use the full scope; table result counts follow the selected filters.

Status includes Open transfers, Waiting, On Board, Done, All transfers and Deleted records. Export cargo exports the complete filtered result to CSV or Excel, including results beyond the current page. Cargo Excel import is not supported; personnel Excel import is a separate workflow.

Backup and recovery

Create a Cargo backup from Cargo > More. Restore checks the selected database and makes a safety copy before replacing the current ledger. A failed restore attempts to recover the previous ledger. If both restore and recovery fail, writes are blocked and the safety-copy location is retained for recovery. Keep all recovery files until the ledger has been restored successfully.

Personnel has its own database, backups and restore controls in Personnel > Settings. Cargo and Personnel backups are not interchangeable. Do not put a backup inside an application installation folder. Exports cannot overwrite either live database, a companion database, or protected recovery files.

Settings and appearance

Choose Light or Dark appearance and a 10, 11 or 12 pt interface font. Changes apply immediately. Inter is bundled with the application. Choose the business time zone used for recorded completion dates. Port name is shared by Cargo, Personnel and newly generated plan headings; historical plan headings retain their saved values.

Cargo database and backup directories can be changed independently. Moving a database validates the copied ledger before switching and retains the original. An existing destination database is not overwritten. Personnel settings independently control its database, backup directory and Plan transfer vessel. A blank Personnel transfer vessel uses the Cargo setting.

The MarineOps rename retains the previous data directories, saved settings and single-instance identity. Existing databases and saved plans remain available without reimporting data.

Keyboard shortcuts

F1 opens contextual help. F5 refreshes the current workspace. Ctrl+F focuses search and Ctrl+N opens the new Cargo form where available. In the personnel draft, Ctrl+Z undoes a cell edit and Ctrl+Shift+Z redoes it. Double-click a stop assignment, or press F2, to choose a visit. Esc closes the Dashboard roster drawer. Tab moves through available controls.

Personnel and berthing plans

Open Personnel > Import Excel, review the worksheet, mapping, vessel matches and duplicate-row decisions, then confirm the import. Sign-off and Sign-on sections are read independently. Passport and identity numbers, company information, laptop details and Mark fields are excluded. Retain original source files separately. Append keeps missing entries; a confirmed complete replacement can remove missing entries from the crew list.

Berthing plan > More > Generate plan creates the initial independent route. The left side controls visit order; the personnel table controls inclusion and pickup/drop visits. Cargo voyage order is unchanged. Add crew and Edit crew update the main crew list. Changes to crew information, including From and To, automatically update the open draft and create a new current version of affected saved Final plans. Earlier versions remain available. Regenerating the plan is not required for these crew edits.

Double-clicking Name or Position changes only the draft. A draft-only override remains while the corresponding main-list field is unchanged; a subsequent main-list change to that field takes precedence. Stop comments are saved with the plan and exported. Unavailable assignments remain review issues rather than being treated as completed work.

Save draft can retain review issues. Save version requires valid assignments. Version history loads a saved snapshot; Edit plan refreshes it into a new draft. Export Excel first asks for a file path; cancelling does not create a version. If saving succeeded but writing Excel failed, the saved version can be exported again.

Unsaved changes offer Save draft, Discard or Cancel when leaving, switching lists or loading another version. Source invalidation preserves changes in the draft-recovery folder beside the personnel database. Recover draft rebuilds against current sources for review.

Linked transfer legs and Excel

For a person who is delivered to a vessel and collected again later, select the first leg and choose Next leg. From starts at the preceding destination; enter the new To. A later leg requires another actual pickup visit after the preceding delivery, including a port or the transfer vessel. It cannot collect on the same visit as that delivery.

To link existing entries, select the same person's rows and choose Link legs. Review the suggested order; drag or use Move up and Move down, then Link in this order. Equal names alone do not identify one person. Discontinuous routes, branches and cycles are rejected. Leg shows the sequence number. Changing a chain recalculates affected assignments.

When a first leg originates on the configured Plan transfer vessel, only a destination Drop is required. An empty From does not imply that the person is already aboard. Other origins require normal collection. Add, move or remove port calls to match the actual trip.

Berthing Plan uses four action rows per call: Drop passengers, Pick up passengers, Drop material and Pick up material. Counts, numbering, names and positions wrap in the action cell. Column C is 60 characters wide. The print layout is A4 portrait at 100% scaling, with bounded widths and continuation rows/pages for long lists and comments. Stop groups are kept together where possible. Saved snapshots retain their original text.

Workspace and history management

Dashboard, Cargo and Personnel share the MarineOps navigation. Each workspace has an About button. Rename changes a crew-list label without changing crew, leg or plan identities. Personnel displays crew only; material records remain managed in Cargo.

Version history > Remove selected hides selected versions. Clear history clears the visible list after confirmation. The underlying historical snapshots remain available to backups and audit; crew lists and Cargo are not deleted. Later saves continue the version numbering.

Workbench controls

Cargo provides Pick up, Deliver, Details and Edit fields above the table. All voyage visits wrap into the route area. Status is a combined filter. More > Show Completed Date controls the optional date column; one-page results do not show unnecessary pagination.

In Personnel, Pick up and Drop choose actual visits. Changing one endpoint retains the other endpoint when feasible; otherwise both reflect the selected valid pair. Repeated visits keep distinct identities. Stop preview shows passenger movements and saved comments. In smaller windows, expand Stop preview or use More > Full personnel preview for the complete schedule.

Dashboard

Dashboard opens by default. Choose the current visit manually; choose it again to clear it. Open current stop opens its Cargo actions. Cargo summary includes unfinished departure backlog and new records in the current voyage, grouped by actual Waiting, On Board and Done states. Older completed cargo is excluded from this departure scope. Current Cargo actions preview is limited to 200 rows; View all opens the full Cargo result.

Current stop personnel shows Boarding (joining the stop vessel) and Leaving (leaving it), with names, positions and movement. These are planned movements, not execution confirmations. Latest saved plan (automatic) follows the newest current plan and updated crew list. Choosing a historical version keeps its snapshot identity; a stale historical source requires review.

Personnel and Cargo visit IDs may differ. The exact visit is preferred, then a unique call to the same vessel. Multiple independent calls require selecting the actual Plan visit. No current visit, no saved plan or an invalid source shows a clear message instead of old counts.

The combined roster scrolls independently. View full list opens a drawer with All, Boarding and Leaving tabs and name/position search. Searching does not change the headline counts. Esc closes the drawer. Personnel plan progress counts each transfer leg once: drops before Current are Completed; drops at Current or later are Pending. Returning to an earlier visit also changes this plan-based progress.

History integrity and complete printing

Removed personnel legs retain their original history when active legs are relinked. Invalid active chains roll back as a whole. Long passenger lists and comments are exported in full using continuation rows/pages; group counts appear only at the start while numbering continues.

Transfer Details retains all 19 electronic data columns. Transfer Print provides the business fields and comments for printing. Cargo exports use A4 landscape and retain all nine source columns; very long cells also receive a Cargo Print sheet while the original data remains in Transfers.

Automatic berthing planning

Choose Personnel > Berthing plan > Auto plan. Select trip materials, retain required calls or existing assignments, then Calculate complete route. Review every pickup, delivery and call count before choosing Use this route. Each actual vessel call counts once, including repeated calls. Exact search proves minimum vessel calls and then minimum port calls; a limited complete candidate does not claim a minimum.

The model assumes one transfer vessel, sufficient capacity and no time windows. Sign-on passengers board at an actual port call before delivery; Sign-off passengers reach port after collection from their vessels. Material execution status is unchanged. The route menu provides Check complete route, Undo auto plan and Keep / release selected call. Manual route editing remains available. Crew or route changes invalidate a previous minimum-call proof; run Auto plan again when a new proof is needed.

Crew-change port calls

Sign-on uses the configured port as From; enter To or Vessel. Sign-off uses the port as To; enter From or Vessel. New direct-departure plans include the departure port, and plans with returning Sign-off passengers include a return call when needed.

For a trip that visits vessels, returns to port and then visits more vessels, place Port between the two groups. Collect Sign-off before that port call and load Sign-on at port before onward delivery. Calls to the same vessel on either side of port are separate visits. Removing a necessary port call leaves a review issue. Existing routes and historical snapshots retain their identities; unresolved vessel names still need review.

Crew vessel matching

Imported Sign-on and Sign-off directions are retained even when a vessel is unresolved. Explicit reviewed aliases take priority. Unambiguous whitespace/hyphen variations and confirmed abbreviations such as BVC, SPR and BGP INV can match active fleet names. Ambiguous or inactive matches require an explicit selection. Changing a vessel mapping refreshes the import preview and is saved with the confirmed import. Existing lists do not need duplicate imports.

Names and text casing

Personnel imports and manual forms normalize names and positions. Names retain apostrophes and hyphens; positions preserve known abbreviations such as NAV, QC and HSE. Hover over imported Name or Position to inspect the Excel original. Keep Excel spelling and Keep my spelling bypass automatic casing and survive refresh/reopening.

Cargo forms preview After saving while protecting known abbreviations, units, models and mixed-case brands. Unfamiliar codes may need review. Line breaks, physical identifiers, vessel names and comments are preserved.

To review existing values, use Cargo > More > Normalize existing item names or the crew-list More > Normalize existing names / positions. Compare Original and Suggested, select changes and Apply selected changes. Uncertain codes are not selected by default. Audit history retains originals; identities, routes and execution states remain stable. Current Final crew plans refresh automatically while earlier versions retain their text.
